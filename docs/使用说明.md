## 0. 一分钟上手

1. 电视棒插到手机的 OTG 转接头上 → 系统弹窗点【允许】（只在第一次插时问）。
2. 打开 App → 点【开始接收】。
3. 有车经过时，上面的表格会自己填上：车次、方向、速度、公里标、离你多远、还有多久到。
   正在接近的车会响一声提示音，进入告警距离会急促告警 + 振动。
4. 想听广播、对讲机、航空塔台 → 点右上角【收音机】。

一句话：**左边那个模式是"收车"，右边那个模式是"收音机"。**

## 1. 装好、插上

### 需要什么

| 项目 | 要求 |
|---|---|
| 手机 | Android 8.0 以上，**64 位（arm64）**；需要支持 USB-OTG |
| 电视棒 | RTL2832U 芯片的 RTL-SDR 棒（蓝色小棒、RTL-SDR Blog V3 等都行） |
| 转接头 | USB-OTG 转接头（Type-C 或 Micro-USB，看手机） |
| 天线 | 棒自带的拉杆天线就够收本地 FM；收铁路信号建议接好一点的天线、放在窗边 |

### 驱动：不用另外装

App **自带** rtl_tcp 驱动（设置里的「使用内置驱动」，默认就是勾上的）。
插上棒、点【开始接收】即可，不需要装任何第三方 App、不需要 root。

如果你更习惯用外部驱动 App（SDR Touch 的驱动之类），把设置里的
「使用内置驱动」取消勾选即可 —— 此时点【开始接收】会去拉起那个 App。

### 台架模式（用电脑上的电视棒当信号源）

没有棒、或者想用电脑上那根更好的棒时用：

1. 电脑上装好 rtl-sdr 工具，运行（把电脑的棒变成网络数据流）：

   ```
   rtl_tcp -a 0.0.0.0 -p 1234
   ```

2. 手机与电脑连同一个 Wi-Fi。
3. App 的【设置】里勾上「台架模式」，服务器地址填 `电脑IP:1234`（端口固定 1234）。
4. 点【开始接收】。

台架模式不拉起任何驱动，直接连那台服务器。协议细节见 [BENCH_MODE.md](BENCH_MODE.md)。

> 这一条路也是"非 RTL"设备的通用接法（Airspy、SDRplay 的 RSPduo/RSPdx/RSP1B 等）——
> 只要有台机器能把设备变成 rtl_tcp 服务器就行，见
> [其它"非 RTL"设备 / 电脑当桥](#其它非-rtl-设备--电脑当桥)。
> **RSP1 / RSP1A / RSP2 不用这么绕**：它们用的是 Mirics 芯片，手机插上就能直连，
> 见 [接 RSP1 / RSP1A / RSP2（Mirics 芯片，手机直连）](#接-rsp1--rsp1a--rsp2mirics-芯片手机直连)。

## 2. 接近器模式（列车接近预警）

### 2.1 基本操作

| 按钮 | 作用 |
|---|---|
| **开始接收** | 起驱动 + 开始解码。第一次插棒会先要 USB 授权 |
| **停止** | 停止解码并关掉驱动（拔棒前先点它，更干净） |
| **设置** | 频率、增益、PPM、告警距离等，见 [第 7 节](#7-设置逐项说明) |
| **关注车次** | 只盯你关心的车；还能开「乘车模式」，见 [2.7](#27-关注车次乘车模式) |
| **清屏** | 清空当前显示和下面的"最近列车"表 |
| **定位本站** | 用手机定位把"本站/公里标"对上线路，见 [2.8](#28-定位本站) |

### 2.2 先看这四项

不用懂报文，先看这四格就能判断"有没有车、离我多远"：

- **状态**：接近 / 即将到达 / 远离，接近时会标黄
- **距离**：那趟车离你多少公里（要用过「定位本站」才有）
- **速度**：km/h
- **方向**：上行 / 下行

### 2.3 信息表 16 格逐项含义

| 格 | 含义 |
|---|---|
| 到达 | 还有多少秒到（"120s"） |
| 时刻 | 预计到达的时刻（"14:23:05"） |
| 本站 | 你所在位置的线路公里标（用过「定位本站」才有）；乘车模式下这格变成**位置**，显示你坐的这趟车现在在哪 |
| 距离 | 车离你几公里 |
| 状态 | 接近 / 即将到达 / 远离 / 已过 |
| 方向 | 上行 / 下行 / 未知 |
| 速度 | 车速 km/h（车自己报的） |
| 公里 | 车当前所在公里标 |
| 机车 | 机车号 |
| 代号 | 机车/车次代号 |
| 线路 | 匹配到的线路名（依赖线路公里标库） |
| 类别 | 客 / 货 / 动车 等 |
| 端位 | 1 端 / 2 端（车头的方向端） |
| 经度 / 纬度 | 车报的位置（部分报文带；范围不对会显示「存疑」，宁可不显示也不显示错的） |
| 样本 | 这条线路已经积累了多少组里程样本（定位和匹配要用） |

### 2.4 状态栏四行（排查问题用）

```
▲ 821.2375M  G:19.7  P:-31  S:960k
RSSI:-46 阈:-55 RX:ON H:700
FERR:+12 AFC:+8 S:0.93
PK:821.237312M Δ:+0.3k -26dB
```

| 缩写 | 含义 |
|---|---|
| ▲ 频率 | 正在收的频率；应该是 821.2375 |
| G | 增益 dB；P | PPM 校正值；S | 采样率 |
| RSSI | 当前信号强度 dB；**阈** | 门控阈值（比它强才处理） |
| RX | 门控有没有打开（ON/OFF）；H | 释放保持 ms |
| FERR | 测到的频率偏差 Hz；AFC | 自动频率跟踪的修正量 |
| S（第三个） | 同步质量（越大越稳） |
| PK / Δ / dB | 频谱峰值频率 / 与目标频率差 / 峰值电平 |

**怎么用**：收不到车时先看 **RSSI** 和 **PK Δ**。
RSSI 一直在阈以下 → 信号太弱（天线、位置、增益）；PK Δ 偏得大 → 频率偏了，做一次 [PPM 校准](#5-ppm-校准把频率校准准)。

### 2.5 频谱图

中间那条柱状图是 960 kHz 带宽内的实时频谱。

- 右边那根**黄柱是电视棒的直流尖峰**，是正常现象（App 已经靠 DC 避让绕开它，不影响解码）。
- 有信号时你会看到目标频率附近的柱子在跳。

### 2.6 最近列车

下面是最近收到的车，按时间倒序：车次 / 方向 / 速度 / 公里标 / 机车 / 时间。

- 关注的车次会**高亮红色**；乘车模式下**你自己坐的那趟显示蓝色**（方便一眼和路过的车分开）。
- 行数按屏幕高度定（高屏 16 行，普通屏 10 行）。

### 2.7 关注车次（乘车模式）

点【关注车次】：

| 项 | 说明 |
|---|---|
| 关注的车次或机车 | 逗号分隔，比如 `K1234,T567`；留空 = 全部车都显示 |
| 乘车模式 | 填**你自己坐的车次**。填了以后：这趟车只在下面「最近列车」更新，不刷上面的大面板（不然你一上车大面板就被它刷屏，看不见路过的车），提示音也不会被它触发 |
| 关注模式：严格 | 勾上 = **只**显示关注命中的车，其他一律留空；不勾 = 全都显示，关注的高亮 |
| 错包拦截 | 丢掉纠错也救不回来的报文（默认开）。关掉会显示更多信息但也会更乱 |
| 干扰预警 | 探测到严重干扰时提示 |

全角逗号（，）、顿号（、）都会自动当成半角逗号。

### 2.8 定位本站

【定位本站】用手机定位，把"你在这里"换算成线路上的公里标，之后"距离/到达/状态"才有意义。

- 点之前建议**在室外/窗边**，等 GPS 拿到位置。
- 如果表里"样本"还是 0，说明这条线路的里程样本还不够，多收一会儿再定位。
- **乘车模式下不用点它**：你的位置跟着本车公里标实时更新，点它反而没意义（会提示你）。

### 2.9 告警

- **提示音**：每解出一趟新出现的车次响一声（走媒体音量，静音就没了）。
- **接近告警音 + 振动**：车正在接近、且距离小于「告警距离」时急促提示。
- 两个都在【设置】里开关，告警距离默认 5 km。

### 2.10 语音播报

「最近列车」这一行右边有个 **☐ 语音** 开关，打开后每解出一趟车就念一遍：

> **车次，线路，上下行，速度 xx 公里每小时，公里标 xxxx.x，距离 xx.x 公里**

- **没解出来的项自动跳过**：比如还没定位过本站，就没有"距离"这一句；基础帧刚到、
  线路还没解出来时，会**等 0.2 秒左右把扩展帧等齐再念**，不会念一半。
- 同一趟车**不会反复念**（10 分钟内只念一次），车流密的时候也不会排队积压。
- 乘车模式下自己坐的那趟车不念（跟提示音一致）。
- 第一次打开开关要等一两秒（系统语音引擎在初始化）。如果这台手机的语音引擎
  用不了，App 会直接说明原因并给一个【去设置】按钮跳到系统「文字转语音」页。

### 2.11 列车接收历史

「最近列车」右边还有一颗【历史(N)】按钮（N = 今天已归档几趟），点开就是**按趟归档的接收记录**。
详见后面 [列车接收历史](#列车接收历史按趟归档) 一节。

## 3. 收音机模式

点右上角【收音机】进入，点【接近器】回来。

### 3.1 两种模式：频率模式 / 信道模式

| | 频率模式（自由调谐） | 信道模式 |
|---|---|---|
| 频率 | 随便调 | **跟着信道走**，不能手改 |
| 上下键 | 调频率 | 切上/下一个信道 |
| 适合 | 找信号、听陌生频点 | 常听的台 |

【切换模式】按钮在两种模式之间切。

### 3.2 调谐

- **◀ 减 / 加 ▶**：按当前步进加减频率。
- **步进**：点它循环切换（12.5 kHz / 25 kHz / 100 kHz …）。铁路/对讲常用 12.5 kHz。
- **点频率大字**：弹出数字键盘，直接输频率（MHz）。
  - 最多 4 位小数；比如 `457.2125`、`121.5`、`98.7`。输入框初值会自动去掉没用的尾零（95.9000 显示成 95.9，而 821.2375 原样保留，不会被截成 821.238）。
  - 键盘上还有【清空】【退格】【确定】【取消】。
- **频率显示**只保留 3 位小数（95.9、457.825），方便一眼读；实际调谐精度更高。

### 3.3 制式

点【制式】循环切 NFM / AM / WFM：

| 制式 | 用在哪 |
|---|---|
| **WFM** | FM 广播（87~108 MHz），带宽宽、带立体声导频 |
| **NFM** | 对讲机、铁路/调车、业余段（400/150 MHz 段） |
| **AM** | 航空（118~137 MHz）、部分中短波 |

### 3.4 亚音（CTCSS）

对讲机常用亚音来做"只开这一路"的静噪。点【亚音】选一个频率（88.5 Hz 等），
选了以后**只有带这个亚音的信号才出声**，用来在嘈杂的信道上只听某一路。

已知亚音值就选；不确定就保持"关"。**扫描不会去识别亚音**（亚音要靠连续听 1 秒以上才能分开，和扫描"快"的目标冲突），扫到频点后想开亚音，在信道里填。

### 3.5 静噪与音量

- **静噪**：勾上"开启"才有效；滑块往右 = 更安静（只放强信号），往左 = 更容易听到弱信号。
  门限会随底噪自动浮动，不用你反复调。
- **音量**：独立于系统音量。

### 3.6 频谱

收音机页也有频谱，中央的尖峰同样是直流尖峰。

## 4. 扫描（找频点）

**用来干什么**：不知道附近有什么信号时，一路扫过去，把有信号的频点列出来，点一下就能听。

### 4.1 怎么开始

1. 先把频率调到你关心的范围**中心**（比如想扫 400~420 MHz 就调到 410）。
2. 点【扫描】→ 弹出选项框：
   - **用峰值自动微调频率**（默认开）：扫到信号后用峰值 bin 把频率修得更准。
   - **门限**：见下。
3. 点【开始】→ 出现结果窗，扫描一直进行，**不点【停止扫描】不会停**。

### 4.2 范围和一趟要多久

- 范围 = 以当前频率为中心**上下各 10 MHz**（共 20 MHz），结果窗里写着确切范围。
- 一趟约 **2~3 秒**（本机实测 2.2 秒）。扫完一趟接着扫下一趟，反复扫，越扫越准。

### 4.3 门限（把弱信号滤掉）

门限 = **比底噪高多少 dB 才算信号**，默认 7。

- 底噪 -55 dB 时，门限 7 意味着 -48 dB 以上才算信号。
- **嫌列表里杂音多 → 填 12、15**；怕漏掉弱信号 → 填 5、6。范围 2 ~ 40。
- 扫描**进行中也能改**：点结果窗里的【门限】，改完立刻生效，表里低于新门限的行会**马上消失**。
- 结果窗状态行一直显示"底噪 … 门限 …（底噪+N）"，方便你判断。

### 4.4 制式

复核（确认"这个频点真有信号"并听一下）用的就是你**外面设的制式**：

- 想扫 NFM → 外面设 NFM；想扫 AM → 外面设 AM。
- 扫描窗里有一颗【制式】键，扫的过程中也能直接换（上面那颗制式按钮跟着变）。
- 窄带信号在频谱上分不出 NFM 还是 AM，所以不做"自动判断"，按你设的来。

### 4.5 结果表怎么读

```
01  95.891 MHz
    WFM  -43 dB  占用 100 kHz  已复扫 7 次
```

| 项 | 含义 |
|---|---|
| 频率 | 信号频率（3 位小数） |
| 制式 | 复核时用的制式 |
| 强度 | 实测电平 dB，越接近 0 越强 |
| 占用 | 信号带宽（比峰值低 6 dB 的宽度）。200 kHz 左右 = FM 广播；十几 kHz = 窄带 |
| 已复扫 N 次 | 这个信号被重复扫到 N 次，频率是 N 次平均出来的 |
| ⚠过载 | 信号太强把前端打饱和了，**这次频率不可信**，请降低增益或离远点 |

### 4.6 越扫越准

同一个信号每再扫到一次，App 就把新估计和旧估计**平均**一次，所以：

- 刚出现时可能显示 95.905，扫几趟后落到 95.891、95.900……
- 这正是"持续扫描"的意义：**让它多扫几趟，频率会更准**（窄带信号的峰值估计会受调制影响偏个几百 Hz 到一两 kHz）。
- 同一个台**只会有一条**：宽的按"广播级"容差合并，窄的守住一个格子（12.5 kHz 的相邻信道不会并掉）。

### 4.7 点一下、长按

| 操作 | 效果 |
|---|---|
| **点一行** | 问"把 xxx 设为当前频率？"，点【是】→ **停止扫描**并切到那个频率（制式也跟着切） |
| **长按一行** | 存成信道（走和收音机里【存到信道】一样的选信道流程） |

### 4.8 结果窗上的按钮

| 按钮 | 作用 |
|---|---|
| **停止扫描** | 停；停在最强那个信号上；结果表留着 |
| **再扫一趟**（停着时显示） | 回到选项框重新开始 |
| **门限** | 扫描中改门限（不会关掉本窗口） |
| **清空** | 把结果表清空（主界面按钮上的个数也一起清掉） |
| **关闭** | 只关这个窗口，**扫描继续** —— 主界面那颗按钮此时是「扫描结果(N)」，点它随时回来 |

### 4.9 扫不到 / 扫得不对

- **一个信号都没有**：门限调小（填 5、6，甚至 3）；确认天线接好；确认这个频段附近确实有信号。
- **全是杂音、一片弱信号**：门限调大（12、15）。
- **频率对不上已知台**：看结果里是不是标了「⚠过载」（降增益），或者先做一次 [PPM 校准](#5-ppm-校准把频率校准准)。
- **扫得很慢**：正常一趟 2~3 秒；如果明显更慢，可能是驱动没给你提速的采样率（App 会自动退回 960 kS/s 慢一些跑，功能不受影响）。

## 5. PPM 校准（把频率校准准）

### 为什么要做

每根棒的晶振都有偏差（几 ppm ~ 几十 ppm）。821.2375 MHz 上偏 30 ppm 就是 **±25 kHz**，
足以让解码失败。校准一次就能长期用。

### 自动校准（推荐）

【扫描】选项框里的【PPM 校准】→【自动：自己找本地 FM 广播台】：

1. App 扫一遍 FM 广播段（87.5~108 MHz），找最强的台，吸附到 100 kHz 栅格
   （国内 FM 频点都在这个栅格上）。**为什么信广播**：发射台锁 GPS，比手台准几个数量级。
2. 停在这个台上量**载波频偏**（用 FM 鉴频器的直流，不受节目内容影响，精度约 ±15 Hz）。
3. 自动算出建议的 PPM、应用、再复测一次，把残差告诉你。

### 手动校准

【PPM 校准】→【手动：用当前正在听的台】：

1. 先调到一个**已知频率**的 NFM/WFM 台（对讲机、广播）。
2. 点手动校准，等它量完。
3. 它会给出建议的 PPM（AM 不行，AM 没有鉴频器）。

### 结果怎么读

- **载波偏 +xxxx Hz**：现在偏了多少（正 = 读出来比真实频率高）。
- **建议 ppm = 当前 ppm + 修正量**，点应用就会写进设置并立即生效。
- 复测残差接近 0（本机实测 -32 Hz）就算成功。
- **每根棒的值不同**；换棒、换转接头后建议重做一次。本机（FC0013）实测是 **-31**。

## 7. 设置逐项说明

点【设置】。改完点【保存并应用】。

### 驱动与连接

| 项 | 说明 |
|---|---|
| 台架模式 | 不拉起驱动，直接连下面的服务器地址（用电脑上的棒当信号源时勾） |
| 使用内置驱动 | 默认勾选。App 自带 rtl_tcp，不需要外部驱动 App；取消勾选则去拉起外部驱动 App |
| 服务器地址 | **只在台架模式下有效**；不勾台架时一律连本机 127.0.0.1 |

### 射频

| 项 | 说明 |
|---|---|
| 频率 MHz | **默认 821.2375 = 全国铁路统一频点**，一般不用改，改错就完全收不到 |
| 增益 dB | R820T：0 ~ 49.6；FC0013：-9.9 ~ 19.7（含负档）。默认 19.7。信号过强出现「⚠过载」时调低 |
| PPM 校正 | 晶振偏差。用 [PPM 校准](#5-ppm-校准把频率校准准)量出来填；符号别填反 |
| RSSI 门控阈值 dB | 比它强才处理，-140 ~ 0，默认 -55。**收不到就调低到 -65** |
| 门控释放保持 ms | 门控关闭后保持多久，0 ~ 10000，默认 700。**报文中间断开就加大** |
| 增益档位（FC0013/FC0012 · R820T · 其它/网络源） | 决定你填的 dB 怎么吸附到设备真有的档位。RSP1 等非 RTL 设备选"其它/网络源"（不吸附，原样转发） |
| RSP1 / RSP2（Mirics 芯片）自检 / 启动驱动 | Mirics 芯片（RSP1/RSP1A/RSP2）插在手机上时点这里：自检 → 启动本机 127.0.0.1:1234，并自动设好台架模式。详见[手机直连](#接-rsp1--rsp1a--rsp2mirics-芯片手机直连) |
| 启用 AFC 自动频率跟踪 | 默认开。跟踪残余频偏，能容忍几 ppm 的偏差 |

### 提示与告警

| 项 | 说明 |
|---|---|
| 提示音 | 每解出一趟车次响一声（走媒体音量，可调为 0） |
| 接近告警音 + 振动 | 进入告警距离时急促提示 |
| 告警距离 km | 正在接近且距离小于它 → 告警，默认 5 |

### 位置与线路

| 项 | 说明 |
|---|---|
| 全局本站公里标 km | 你所在位置的公里标（0 ~ 9999.9，可留空）。知道就直接填，省得定位 |
| 按线路设公里标 | 格式 `线路=公里标`，如 `京沪线=0123.4`；多条用逗号分隔 |
| 列车历史保留天数 | 0 = **永久保留**（默认）；填 180 就只留最近 180 天 |

## 接 RSP1 / RSP1A / RSP2（Mirics 芯片，手机直连）

### 先看型号：芯片是 Mirics 的就能直连

| 能直连（App 自带开源驱动 libmirisdr） | 不能直连 |
| --- | --- |
| SDRplay **RSP1 / RSP1A / RSP2** | SDRplay **RSPduo / RSPdx / RSP1B** |
| 蓝色 **MSI.SDR**、各种 MSi2500+MSi001 一体板 / 克隆板 | 用 SDRplay 自家闭源芯片的其它型号 |

RSP1 / RSP1A / RSP2 用的是 **Mirics MSi2500 + MSi001** 芯片，有开源驱动，可以像 RTL 电视棒一样
**插在手机的 OTG 口上直接用**，不需要电脑、不需要桥。
RSPduo / RSPdx / RSP1B 是 SDRplay 自己的芯片，驱动闭源且许可不允许随 App 分发，只能走
[电脑当桥](#其它非-rtl设备--电脑当桥)。

### 怎么用（四步）

1. 用 OTG 转接头把 RSP 插到手机上（第一次插系统会弹窗问，点【允许】）。
2. 打开 App →【设置】→ 找到最下面那颗按钮：
   **【RSP1 / RSP2（Mirics 芯片）自检 / 启动驱动】**，点一下。
3. 第一次会弹系统授权框 → 点【允许】→ **会自动接着自检**，弹出「自检结果」：
   打开设备、设 960 kS/s、设频率、读增益档的回读值都写在里面。
4. 自检正常 → 点【启动驱动】。App 会在本机 `127.0.0.1:1234` 起一个 rtl_tcp 服务，
   并顺手把【台架模式 ✓ / 服务器地址 127.0.0.1 / 增益档位 = 其它·网络源】设好。
   然后回主界面点【开始接收】就行。

> 换回 RTL 电视棒：把【设置】里的「台架模式」取消勾选即可。

### 自检没通过时，按弹窗说的做

- **弹「没找到 RSP1 类设备」，说一个 USB 设备都没有**
  → 手机压根没给棒子上电。按顺序排：① 换一根线 / 换 OTG 转接头（很多线只能充电）；
  ② 用带供电的 OTG 扩展坞（这种棒子比 RTL 电视棒费电）；③ 看系统里 USB OTG 开关开没开。
  插好之后系统一般会弹一下「已连接 USB 设备」，看到它了再点一次自检。

- **弹「USB 上现在有 N 个设备」**
  → 手机认到设备了，但没有一台是已知的 SDRplay / Mirics 型号。
  这一屏会把**当前挂着的每一台 USB 设备**（VID:PID + 名字 + 系统路径）列出来：
  - 里面有你的棒子 → **点它一下**，App 会强行按 Mirics 芯片打开试一次；
  - 没有你的棒子、或者点了还是不行 → 把**这一屏截图**发给作者，把设备 ID 加进识别表。

- **弹「打不开这个 USB 设备」** → 被别的 App / 系统驱动占着：
  把其它收音机、SDR、电视 App 全清掉，拔了重插再试。

> 想看"手机到底认到了什么设备"（比如排查是不是没认到棒子、认成了什么 ID）：
> **长按**那颗 RSP1 按钮，随时能调出 USB 设备列表。

- **弹「驱动没起来」** → 按弹窗里的清单做；如果自检里采样率/频率回读是 0，
  说明这颗板子的时钟和通用 Mirics 不一样，把自检那一屏截图发作者。

### 和设备无关的一件事：采样率

App 的解调链（DDC、35 kHz 信道滤波、鉴频器）是按 **960 kS/s** 设计的。RSP 走的是
"设备自己要 960k"，App 连上后还会**自己量实际速率**（收前 12 个数据块计时），不对就弹提示
告诉你差多少、该怎么改 —— **不会静默算错**让你以为"这台设备收不到车"。

## 其它"非 RTL"设备 / 电脑当桥

**通用办法**：本 App 只认一种链路 —— **rtl_tcp 协议**（8 位 IQ + 设频率/采样率/增益/ppm 等命令）。
只要有一台机器能把设备变成 rtl_tcp 服务器，**任何 SDR 都能用**。

### 什么时候需要它

- SDRplay 的 **RSPduo / RSPdx / RSP1B**：驱动是**闭源库**（`libsdrplay_api`），
  许可**不允许随 App 分发**，Android 上也没有现成的 rtl_tcp 服务器 App；
- Airspy、SDRplay 之外的其它 SDR：同理。

这类设备需要一台装了对应驱动的机器当"桥"：电脑、树莓派、路由器都行。

### 怎么做（电脑/树莓派当桥）

1. 那台机器上装：**SDRplay API** + **SoapySDR** + **SoapySDRPlay**，再装 rx_tools（提供 `rx_tcp`）。
2. 跑起来（把 RSP 变成 rtl_tcp 服务器）：

   ```
   rx_tcp -d driver=sdrplay -s 960000 -f 821237500 -g 40
   ```

   `-s` 采样率、`-f` 频率、`-g` 增益（RSP 的增益单位就是 dB）。
3. 手机和它连同一个网络，App【设置】里：
   - 勾上「**台架模式**」（= 用外部服务器，名字是历史原因）
   - 「服务器地址」填那台机器的 IP（端口固定 1234，不用写）
   - 「**增益档位**」选「**其它/网络源(RSP1 等)**」——
     这样你填的 dB 会原样转给服务器，不会被 RTL 的档位表改掉
4. 【开始接收】。

### 两个必须注意的点

- **采样率要正好 960 kS/s**：App 的解调链（DDC、35 kHz 信道滤波、鉴频器）都是按 960 kS/s 设计的。
  桥那头的服务器能给多少要看它的驱动，不一定是 960k。
  App 连上后会**自己量实际速率**（收前 12 个数据块计时），不对就弹提示告诉你差多少、该怎么改 ——
  **不会静默算错**让你以为"这台设备收不到车"。
- 端口固定 **1234**（rtl_tcp 协议规定）；桥那头要监听 `0.0.0.0`，只监听 `127.0.0.1` 手机连不上。

## 列车接收历史（按趟归档）

**入口**：接近器页 →「最近列车」右边的【历史(N)】。**接收中或停止后都能看**（记录存在磁盘上）。

### 一行 = 一趟车

```
01   T358  上行  特快旅客列车
     17:36:52~17:38:10   0158.9→0110.0 km   6 条
```

| 项 | 含义 |
|---|---|
| 车次 / 方向 / 类别 | 取自报文 |
| 起止时间 | 这趟车**第一次**和**最后一次**被收到的时间 |
| 起止公里标 | 首末公里标（箭头方向 = 车往哪开） |
| N 条 | 一共收到几条报文 |

**点一行**看详情：日期、机车（换挂会显示 A → B）、线路、端位、经纬度（首次/最后）、
最大速度、报文数。经纬度只有扩展帧才带，没收到就写"这几条报文里没有"。

### 一趟车是怎么切分的

- 同一车次，距上一条 **< 30 分钟** → 还算同一趟（继续更新）
- 间隔 ≥ 30 分钟 → **新的一趟**
- **方向翻转**（上行↔下行）→ 新的一趟（换端了）
- 公里标跳变 > 200 km 且间隔 > 5 分钟 → 新的一趟（同车次重号）
- **跨零点不切断**：23:59 和 00:05 是同一趟，归到前一天
- 基础帧只有数字（`57`）、扩展帧才有字母前缀（`Z57`）—— 这是同一趟，只记一条

### 导出 / 导入

| 按钮 | 说明 |
|---|---|
| **导出** | 选范围（今天 / 最近 7 天 / 全部）和格式（**CSV** / **JSON**），然后选保存位置 |
| **导入** | 选一个本 App 导出的 CSV 或 JSON，自动合并；**按"日期+车次+开始时间"去重**，已存在的跳过 |

- **CSV**：UTF-8 带 BOM，Excel 直接双击不乱码，表头中文；适合自己统计/给别人看。
- **JSON**：无损（含经纬度、报文数、最大速度等），换手机时用它搬记录。
- 导出位置你自己选（下载目录、网盘 App 等都行），**不需要存储权限**。

### 保留多久

默认**永久保留**（一天一个文件）。设置里有「**列车历史保留天数**」，填 180 就只留半年，
填 0 = 永久。

### 记录存在哪、会不会丢

- 存在 **App 私有目录**（`Android/data/…/files/history/日期.json`），一天一个文件。
- **卸载 App 会一起删掉** —— 所以想长期留档就定期【导出】。
- 写盘有 5 秒节流（停止接收时会立刻落盘），最多丢 5 秒内的更新，不会丢整趟车。

## 8. 常见问题

**Q：点了开始接收，一直"等待信号"、RSSI 很低怎么办？**
1. 看状态栏 **RSSI**：如果一直在门控阈值以下 → 调低增益？不，是信号太弱：换天线/换位置（窗边、室外）、或调低「RSSI 门控阈值」到 -65。
2. 看 **PK Δ**：偏得多说明频率不准 → 做一次 PPM 校准。
3. 确认频率还是 821.2375 MHz，制式不是被改成别的了。

**Q：提示"没有检测到 RTL-SDR 驱动"？**
- 勾上「使用内置驱动」重试；
- 还不行就拔插一次棒（USB 权限要重给）；
- 台架模式下请确认电脑端 `rtl_tcp` 在跑、地址端口填对、手机和电脑同一 Wi-Fi。

**Q：有信号、有车次，但没声音/没提示音？**
- 提示音走**媒体音量**，先确认没静音；
- 设置里【提示音】【接近告警音+振动】有没有关；
- 告警音只在"接近且小于告警距离"时响。

**Q：收音机模式没声音？**
- 【静噪】开着且滑块太靠右 → 往左拉；
- 音量滑块；
- 制式选错了（比如用 NFM 收 FM 广播，声音会又闷又小）。

**Q：扫描扫不到东西？**
见 [4.9](#49-扫不到--扫得不对)。

**Q：耗电/发热？**
SDR 解码是持续满负荷运算，插着棒连续接收本来就热。长时间不用就点【停止】。

**Q：App 能不能后台跑？**
可以：接收/收音期间有一个常驻通知（前台服务），锁屏后继续解码/出声。
但插着棒就在满负荷耗电与发热，不用时点【停止】或拔掉。

**Q：语音播报不响 / 念得不全？**
- 念的内容按"解出来了什么"来：没定位过本站就没有"距离"；基础帧刚到时会等扩展帧齐了再念。
- 完全不响：点【去设置】到系统「文字转语音」里确认装了语音引擎、并把语言数据下好
  （国产 ROM 常见问题是自带的引擎不允许第三方 App 调用，装一个如"Google 语音服务/讯飞"再选它）。
- 走的是**媒体音量**，先确认没静音。

**Q：我有 RSP1/RSP2，能直接用吗？**
- **RSP1 / RSP1A / RSP2（Mirics 芯片）**：能，**插手机上直接就用** ——
  【设置】→【RSP1 / RSP2（Mirics 芯片）自检 / 启动驱动】，按弹窗走两步（自检 → 启动驱动），
  然后【开始接收】。详见[手机直连那一节](#接-rsp1--rsp1a--rsp2mirics-芯片手机直连)。
- **RSPduo / RSPdx / RSP1B**：芯片不同、驱动闭源，得找一台装了 SDRplay API 的电脑/树莓派，
  用 rx_tcp 把它变成 rtl_tcp 服务器，手机走【台架模式】连过去。详见[电脑当桥那一节](#其它非-rtl设备--电脑当桥)。
- 无论哪条路，如果提示"实际采样率不是 960 kS/s"，按提示把服务器（或自检里的设置）改成 960000。

**Q：插上 RSP1 点自检，说"没找到 RSP1 类设备"怎么办？**
两种弹窗含义不同：
1. 说**一个 USB 设备都没有** —— 手机没给棒子上电（换线/换 OTG 头、用带供电的扩展坞）。
2. 列出**一屏 USB 设备** —— 手机认到设备了，但没有一台是已知的 Mirics 型号。
   列表里有你的棒子就**点它一下**强行按 Mirics 打开；点了还是不行，把那一屏截图发给作者加进识别表。

**Q：接收历史在哪？怎么备份？**
App 私有目录里，一天一个文件；**卸载会丢**，所以要长期保留就定期【导出】（CSV/JSON）。

**Q：能录音吗？**
当前版本没有录音功能。
